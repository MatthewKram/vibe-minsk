# V I B E 15.2 — Realtime

V15.2 добавляет постоянное WebSocket-соединение между Mini App и Cloudflare Worker через Durable Objects.

## Что обновляется без перезагрузки страницы

- новые, отредактированные и удалённые сообщения внутреннего чата;
- счётчики непрочитанных чатов;
- новые входящие заявки;
- изменение статуса заявки после принятия/отклонения;
- появление нового участника после принятия заявки;
- выход и удаление участника;
- изменение количества мест/участников;
- создание нового события;
- редактирование события, статуса и обложки;
- внутренние уведомления V I B E;
- счётчики входящих заявок/уведомлений.

## Telegram-бот

Внутренний чат по-прежнему НЕ дублируется в Telegram. Telegram используется только для разрешённых системных уведомлений.

## Обновление с V15.1

Лучше заменить файлы из V15.2 PATCH с сохранением их путей и сделать Commit в GitHub.

Cloudflare сам запустит build/deploy.

### SQL

Ничего запускать в Supabase не нужно.

### Secrets

Новых secrets или variables нет. Существующие `SUPABASE_SECRET_KEY` и `TELEGRAM_BOT_TOKEN` остаются без изменений.

### Cloudflare Durable Object

`wrangler.jsonc` теперь содержит binding `REALTIME` и declarative export класса `RealtimeHub` с SQLite storage. При первом deploy Cloudflare должен автоматически создать namespace Durable Object.

Никаких действий в Dashboard вручную для Durable Object обычно не требуется.

## Как проверить

1. Открой V I B E на двух Telegram-аккаунтах одновременно.
2. На аккаунте A отправь сообщение в чат.
3. На B оно должно появиться без обновления страницы.
4. На B подай заявку на событие A.
5. На A заявка должна появиться без перезагрузки.
6. На A прими заявку.
7. На B статус события и доступ к чату должны обновиться автоматически.
8. На A измени название или вместимость события — на B открытая карточка должна обновиться автоматически.

Если WebSocket временно оборвётся из-за сети или redeploy Cloudflare, клиент переподключится автоматически с увеличивающейся задержкой.
